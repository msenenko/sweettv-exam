# Step 3: validation protocol and baselines

Generated by `python3 src/baselines.py`.

## Protocol

- Interactions: `data/interactions.pkl`.
- Fit on ISO weeks 11-20; validate on ISO weeks 21-30.
- Validation truth: shows watched with `frac >= 0.8` in weeks 21-30, deduplicated per user.
- Evaluated users: all 1,260 submission users. Users with no truth receive MAP@5 = 0 and remain in the all-user mean; the truth-user mean uses only the 1,238 users with non-empty truth.
- Candidate pool: `tv_show_id != 0` shows airing at least once in weeks 21-30 in `export_arh_21-30-final.csv`, restricted to those ISO weeks. Week-21 rows from `export_arh_11-20-final.csv` are not added.
- Candidate pool size: 6,361 shows.
- Repeats of already watched shows are allowed. Rankings contain unique show IDs; duplicates are skipped.
- Fill rule: if a method yields fewer than 5 candidates, append the popularity order for the same `t`, skipping duplicates.
- MAP@5 follows `ml_metrics.apk`, with denominator `min(5, |truth|)`.
- No model was fit; these are reference baselines.

## MAP@5 hand check

Truth `{A,B,C}`, prediction `[A,X,B,Y,C]`:

- A at position 1: precision `1/1`
- B at position 3: precision `2/3`
- C at position 5: precision `3/5`
- `AP@5 = (1 + 2/3 + 3/5) / min(5,3) = (34/15)/3 = 34/45 = 0.755555...`
- Implementation check: `apk(...) = 0.755555555556`.

## Prior expectation

Stated before measurement: user-history should beat popularity at every threshold. Within each baseline, `t=0.8` should beat `t=0.5`, which should beat `t=0.3`, because truth uses `frac >= 0.8` and lower thresholds include incidental zapping. User-history should gain most from `t=0.8` because it counts repeated high-frac airings. Absolute MAP@5 should be modest because truth sets can be much larger than five shows.

## Validation set summary

- Users with non-empty validation truth: **1,238 / 1,260**.
- Truth size mean: **33.993** shows; median: **22.0** shows.

Runtime is the combined time to build training data and evaluate both baselines at that `t`.

## Observed ordering

- Best popularity threshold: t=0.3 (MAP@5 all = 0.472829).
- Best user-history threshold: t=0.3 (MAP@5 all = 0.542232).
- User-history beat popularity at every threshold.
- Both baselines decreased monotonically from t=0.3 to t=0.8, contrary to the prior expectation. With mean validation truth of 34 shows, broader low-threshold training signal was more useful than high-threshold purity.

## Tie-breaking

- Popularity: number of distinct training users with `frac >= t` descending, then `tv_show_id` ascending.
- User-history: number of training airings with `frac >= t` descending, then `tv_show_id` ascending.

## Runtime and seeds

- Total runtime: **1.41 s**.
- Seeds: none. Both baselines are deterministic; no random sampling is used.
